# 04 — Lessons learned from Edith v1

v1 (tag `edith-v1`) taught these the hard way. Each lesson is a rule for the rebuild, with the chunk
that must honour it.

| # | What happened in v1 | Rule for the rebuild | Chunks |
|---|---|---|---|
| L1 | The original code was AI-generated without ever being compiled: ~155 compile errors, five files duplicated under a mistyped package folder, Room set up with `annotationProcessor` (database crashed at startup). | Every chunk must build, run and be exercised on the emulator before it's called done. | all |
| L2 | **Tool calls never worked.** The DTO declared `function` as a string; Ollama sends an object. Every real tool call threw a parse error and the reply failed. | Model Ollama's exact JSON (03 §3.1) with kotlinx.serialization; fixture tests from real responses. | C03, C08 |
| L3 | Tool results were saved to the chat history as `system` messages ("Tool Result: …"), and failed calls left text-form `<tool_call>` replies in history. The model then copied that pattern: **text tool calls 3/3 with history, real calls 3/3 without it.** | Never persist tool exchanges; only `user`/`assistant` rows; strip tool-call text from context; store errors, not fabricated apologies. | C05, C06, C08 |
| L4 | Follow-up tool rounds read tool calls from a field Ollama never sets → silent empty replies. No round limit. | One loop, one code path for every round; cap at 5 rounds; final answer request without tools. | C08 |
| L5 | A weather service parsed wttr.in's `current_condition` (a JSON **array**) as an object → every lookup failed, and Edith apologised. | Parse external APIs from captured real responses in tests; prefer Open-Meteo (structured, keyless). | C09 |
| L6 | Calendar and email returned hard-coded sample data; once tools worked, a model would read "Meeting with Team" as the owner's real schedule. | Never ship fake data behind a real-sounding tool. Unconnected = not offered, and the prompt says so. | C08, C17–C19 |
| L7 | v1 offered 17 tools, 11 of them desktop coding tools (`run_command`, `write_file` …) copied from another project — dangerous and broken on a phone. | Only offer tools that make sense on a phone and are implemented and tested. | C08 |
| L8 | gemma4 "thinking" was on by default: 4–6.5 s per reply. | `think:false` on every request. | C03 |
| L9 | Different `num_ctx` per request and gemma4's huge default context made Ollama swap models on the GPU (3–4 s each way, twice per message). | Same `num_ctx` (16384) on every request. | C03 |
| L10 | The ViewModel was created with `remember { }` → rotation and sign-in wiped live attachments and in-flight replies. Repositories were rebuilt on recomposition. | Real ViewModels via factories; singletons from `AppContainer` only. | C02, C07 |
| L11 | Silence in a voice memo produced a model apology that was sent as the user's message. | `[NO_SPEECH]` marker in the transcription prompt; empty transcript = nothing sent, with a message. | C12 |
| L12 | Ollama only accepts WAV/MP3 audio; Android's default recorders produce 3GP/AMR or M4A. | Record 16 kHz mono PCM WAV with `AudioRecord`; convert other formats in memory. | C12, C15 |
| L13 | Server-side voices: Ollama `phonon` needs Apple MLX (impossible on Windows); an Orpheus + SNAC voice server worked but crackled on the emulator, and the owner removed it. (Re-checked 2026-11-14 on Ollama 0.40.16 for Windows: the `/v1/audio/speech` endpoint exists, but `ollama pull phonon` fails with "this model requires MLX support, but the MLX runtime is not available".) | Phone TextToSpeech only, no network for speech. (Since D21, Edith's own on-device voice is the second engine; still no server speech.) | C13, C36 |
| L14 | Speaking only after the whole reply arrived meant 8+ s of silence. | Stream replies and speak sentence by sentence as they complete. | C06, C13 |
| L15 | Long first sentences delayed speech. | Cut a long opening sentence at a natural pause (comma/semicolon/dash) after ≥25 chars when > ~100 chars. | C13 |
| L16 | `allowBackup="true"` could copy chat history to Google Drive. | Backups off; attachments app-private. | C01 |
| L17 | Settings' "Tap to retry" stopped retrying after an error (regression from another agent). | UI copy and behaviour must match; test the error path. | C04 |
| L18 | Multiple AI agents worked in the same checkout: uncommitted work appeared, a `reset --hard` discarded work, a commit was built on a stale commit. | Branch per chunk from fresh `master`; check `git status` first; never discard others' work without the owner's OK. | all |
| L19 | The emulator's display failed (black screen including the home screen and status bar) and its Bluetooth service crashed; it looked like an app ANR. | Prove where a failure is (e.g. check the home screen) before blaming either the app or the emulator; cold-boot the emulator (`-no-snapshot-load`) when its display misbehaves. | all |
| L20 | DuckDuckGo's instant-answer API (`api.duckduckgo.com`) returns nothing for most real questions ("Pistons game tonight"). Its results pages (`html.duckduckgo.com`, `lite.duckduckgo.com`) do return real results; that's what Jarvis and C10 use. Those pages flagged plain GETs as a bot after 2–3 requests (2026-11-01), but not POSTs like its own search form. | Don't use the instant-answer API. POST to the results pages, fall back to the lite page, and say so plainly when blocked (C10, D3). | C10 |
| L21 | The owner's model names changed between sessions (`gemma4:12b` → `gemma4:12b-it-q8_0`), breaking a saved setting. | Validate the saved model on startup and when sending; offer to pick another if it's gone. | C04 |
| L22 | `adb shell … cat` corrupts binary output; Git Bash rewrites `/sdcard/...` paths; Windows `>` in PowerShell corrupts PNGs. | Use `adb exec-out`, `MSYS_NO_PATHCONV=1`, and Git Bash for binary redirects (05-environment). | testing |
| L23 | (Rebuild, C03 live check, 2026-10-31) On Android 17 (targetSdk 37) the app couldn't reach Ollama at `10.0.2.2:11434` or the PC's LAN address: every request timed out, while `adb shell` reached it instantly. Cause: Android's local network protection; LAN access needs the runtime permission `android.permission.ACCESS_LOCAL_NETWORK`. Proven A/B: revoked → all requests `Timeout`; granted → models, streaming and tool calls work. | Declare it (done in C03) **and request it at runtime before the first connection** (C04); when it's denied, say so plainly instead of "can't reach your server". | C04 |
| L24 | (Rebuild, C07 live check, 2026-10-31) A reply survives rotation (the engine is app-scoped), but **not leaving the app**: ~5 s after the activity closed (Back or Home), Android logged `Destroyed live tcp sockets for uids={…}` and the stream died with `SocketException: Software caused connection abort`, shown as "Can't reach your Ollama server". An app with no visible activity and no foreground service loses its network. | Keep a reply alive with a short foreground service while a turn runs (D13, `chat/service/ReplyService`). Proven A/B on the emulator: without it the reply died ~5 s after Home; with it, 400–700-word replies finished in the background. The notification also needs `POST_NOTIFICATIONS` (asked on the first Send), or Android hides it. | C06, C07 |
| L25 | (Rebuild, C08 live check, 2026-10-31) The app crashed on its first real tool call: the text-call parser's regex `(\{.*})` compiles on the JVM but Android's ICU regex engine rejects the bare `}` (`PatternSyntaxException`, thrown as `ExceptionInInitializerError` when the class loaded). JVM unit tests passed. The `Error` also slipped past the engine's `catch (e: Exception)` and killed the app instead of failing the turn. | Escape `{` and `}` in regexes; test regex-heavy code **on the device** (C08's parser and loop tests are androidTest); the engine also turns a `LinkageError` into a failed turn. | C08, all |
| L26 | (C08 live check, 2026-10-31) Asked "What time is it in Tokyo?", `gemma4:12b` called the tool 5/5; `gemma4:e4b` only 2/5. Otherwise it reused an earlier answer from the conversation, or wrote "Let me check that for you!" without calling anything. For local time both models often answer from the system prompt's date line, which is correct. | Use the 12b model for tool work; judge tool reliability with questions the prompt can't answer. A prompt nudge for small models is possible later. | C08–C11 |
| L27 | (C10 live check, 2026-11-01) With `gemma4:12b`, web answers were right only 1 time in 3: twice it took the right day from search snippets but made up the opponent ("vs Chicago", "Nov 4 vs 76ers"; ESPN said Mon Nov 2 at Charlotte). It also never named its source, though the system prompt asked it to. Once the same requests were put **in the tool result itself** (name the site; read a page when the snippets don't state the answer; never fill in details), it was 3/3 correct and cited its source every time. | Put instructions the model must follow on a result in that result, not only in the system prompt. Check live answers against the source, not just that a tool ran. | C10 |
| L28 | (C14, 30-minute listening check, 2026-11-01) Hands-free used ~26% of a CPU core just listening for the wake word: ONNX Runtime's default thread pool spin-waits between the small model runs (12 a second). Everything else passed, so only measuring caught it. | For always-on models, one thread per session with spinning off (`session.intra_op.allow_spinning = 0`): ~2% with the same scores. Measure CPU over minutes (`/proc/<pid>/stat`) for anything that runs continuously. | C14 |
| L29 | (C18 live check, 2026-11-02) gemma4 got UTC offsets wrong for calendar times: "tomorrow" as `T00:00:00Z`–`T23:59:59Z` (a day shifted 5 hours), and "tomorrow at 3pm" as `15:00-04:00` the day after daylight saving ended (the schema's example used `-04:00`). The confirmation card showed 2:00 PM. | Give the model the current offset (C06's date line), ask for local times without an offset, never show a fixed offset in examples, and treat `Z` and the owner's own zone's offsets as wall-clock time where the user means local time (`ToolArgs.localTime`). Confirmation cards that show the time catch the rest. | C18, C19 |
| L30 | (First release, 2026-11-11) The signed release APK crashed the moment hands-free scored audio: `JNI DETECTED ERROR … java_class == null` in `OrtSession.run`. ONNX Runtime's native code finds Java classes by name, R8 had renamed them, and `onnxruntime-android` ships no keep rules. Every debug build and device test had passed, because debug isn't minified. | Before publishing, install the **release** APK on `Edith_Release_Test` and exercise every native/JNI path (hands-free), not just launch. Keep rules live in `app/proguard-rules.pro` with the reason. | C14, release |
| L31 | (C19, 2026-11-11) Gmail reads `after:2026/11/11` as midnight **Pacific**, so "today" in Michigan began at 3 AM. And the model, asked for "today", wrote yesterday's date. | Turn search dates into local-midnight epoch seconds in code (`GmailQuery.localDates`), and give the model words (`after:today`, `yesterday`) instead of making it do date arithmetic. | C19 |
| L32 | (Gap analysis, 2026-11-11) A kotlinx.serialization parse error's message quotes part of the JSON it couldn't read, and Gmail, Calendar, Ollama and the chat engine logged the whole exception. Email and chat text could reach logcat and crash reports. | `Log` hides parse-error messages in release builds (type and frames only). Never assume an exception's message is safe to log. | C02, C17–C19 |
| L33 | (C19, 2026-11-11) The send card showed only the first 1,500 characters while `send_email` sent the whole body. | A confirmation card must show exactly what will happen: never a preview of something larger. | C08, C19 |
| L34 | (Wake word, 2026-11-11) Edith's Kotlin wake-word detector scores nothing until it has ~2 s of audio (mel windows, then 16 embeddings), unlike openWakeWord's Python, which starts at once. A test clip that starts speaking immediately scored 0.001. In the app it means ~2 s of deafness each time listening starts or resets. | Lead test audio with 2 s of silence. Shortening the deaf window (padding like openWakeWord's Python) is a possible improvement. | C14 |
| L38 | (C36, 2026-11-14) Three traps in putting a native voice into Edith. (1) **sherpa-onnx 2.0 and later cannot run Piper voices**: its built-in espeak-ng phonemizer was removed (`--vits-data-dir` is ignored, generation fails with "phoneme_codepoints is empty"); stay on 1.13.x. (2) The AAR with ONNX Runtime linked in statically adds no `libonnxruntime.so` for arm64 and x86_64, so it doesn't clash with `onnxruntime-android`, but the same AAR carries 32-bit and x86 libraries (one is a second `libonnxruntime.so`) that stop the build at the native-library merge: exclude them in `packaging`. (3) Native code calls the audio callback by name and signature; R8 renames a Kotlin lambda, and the release build dies with `NoSuchMethodError … invoke([F)Ljava/lang/Integer;` as soon as speech is generated (debug works). Use a named class with a keep rule (`SherpaCallback`). | Test the release build of anything with native code first, on a device. |
| L37 | (Andarium, 2026-11-14) Andarium, the Android environment that runs Edith on the owner's iPhone, has **no text-to-speech engine installed**. Edith only spoke through Android's `TextToSpeech`, so there she was silent, and Settings' "install a voice in Android settings" couldn't be followed. | Don't assume a phone has system services (C17b found no Play services; this is no voice). Where Edith needs one, she either carries her own or says plainly what's missing. C36 adds her own on-device voice. | C36 |
| L36 | (C17b, 2026-11-11) The browser sign-in's code reached Edith on 127.0.0.1 while Chrome was in front, but her request to Google failed with `UnknownHostException`, again and again. Android had her `blocked=APP_BACKGROUND` (`dumpsys netpolicy`) and logged `Destroyed live tcp sockets for uids={…}` seconds before each attempt. Loopback still worked; only outside traffic was blocked. One early sign-in passed by timing luck. | Expect **no network while Edith is off screen** (L24) for anything that happens while another app is in front. C17b holds the code and exchanges it when Edith is back on screen (`AppVisibility`). When a request fails only in the background, check `dumpsys netpolicy` for the uid before suspecting the network. | C17b, all |
| L35 | (Wake word, 2026-11-11) The first trained "Hey Edith" woke 8 times an hour on real audio. openWakeWord's `train.py` puts each custom negative phrase in once beside ~10,000 generated ones, so "hey eden" was 1 clip in 450. The model also missed unseen voices saying "Hey, Edith!" with a pause. | Weight custom negatives (40% here), add background-only negatives, and add paused positives. Judge a wake word on voices it never trained on (Windows' David/Zira) and on held-out real audio, beside the published Hey Jarvis as a reference. Training notes: `docs/wake-word-training.md`. | C14 |
