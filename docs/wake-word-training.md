# The "Hey Edith" wake word

Hands-free mode (C14) listens for "Hey Edith" with [openWakeWord](https://github.com/dscripka/openWakeWord). The
phrase has its own small model, `app/src/main/assets/wakeword/hey_edith.onnx` (200 KB), trained on 2026-11-11 on
the owner's PC from synthetic voices. The app picks it up automatically (`WakeWordModel.find`); openWakeWord's
"Hey Jarvis" model stays in the assets only as a test fixture.

## How it was trained
openWakeWord's training steps (its `train.py` and Colab notebook), run on Windows with the scripts in
[`scripts/wakeword/`](../scripts/wakeword/):

| Step | What | Where it came from |
|---|---|---|
| Voices | 13,000 "hey edith" clips + 2,600 for testing; 3,000 of them are "Hey… Edith" with a 0.15–0.6 s pause | Piper voices through `piper-tts`: LibriTTS-R (904 US speakers) and VCTK (109 UK/Irish speakers) |
| Sound-alikes | 10,000 + 2,000 clips that must *not* wake her: 40% from the list in `train_hey_edith.py` ("hey eden", "hey eddie", "edit", "meredith", …), the rest generated by openWakeWord | same voices |
| Realism | Every clip mixed with room echo and background audio | MIT room impulse responses (270); AudioSet balanced-train shards 00–03 (2,000 clips, 5.5 h) |
| Negatives | ~2,000 hours of general audio, as openWakeWord features (17 GB); the AudioSet background on its own | openWakeWord's `openwakeword_features` dataset |
| Training | 50,000 steps, openWakeWord's defaults (32-unit DNN, target 0.2 false wakes/hour) | RTX 5080, ~1.5 h in all |

Why it's not the notebook as-is (Windows): openWakeWord's voice generator needs `piper-phonemize` (Linux only), so
`piper_gen/generate_samples.py` uses `piper-tts` instead; torchaudio 2.11 needs stand-ins for `load`/`info`; the
training data loader runs in-process; a memory-mapped file is trimmed after it's closed; the ONNX export uses the
classic exporter at opset 13 (input `[1, 16, 96]`, what `WakeWord.kt` feeds).

## How good it is
Held-out tests (`evaluate.py`, `check_sapi.py`) at the app's default sensitivity (0.5):

| Test | Hey Edith | openWakeWord's Hey Jarvis, for reference |
|---|---|---|
| Windows' own voices (David, Zira; never heard in training): "Hey Edith", "Hey, Edith!", "Hey Edith, what time is it?" at 3 speeds | **18 / 18** | 6 / 6 ("Hey Jarvis") |
| Same voices saying other things ("Hey Eddie", "Edit the file", "Meredith said hello", …) | **0 / 30** | — |
| New synthetic "hey edith", clean / with echo and noise (5–15 dB) | 92% / 73% | — / 91% |
| Sound-alikes, with echo and noise | 6% | — |
| False wakes on 1.4 h of real audio never used in training (AudioSet shard 04) | **1.5 per hour** | 1.5 per hour |

What that means in practice:
- In a **noisy room it misses about 1 in 4**; say it again, or raise the sensitivity (Settings → Hands-free).
- **"Hey Eden"** wakes it about a third of the time; it's one sound away.
- None of this is a real voice in a real room. That can only be judged on a phone: if it wakes too often, lower
  the sensitivity; too rarely, raise it, and tell me — the training can be repeated with more voices.

Three versions were trained; the earlier two are kept in the work folder (`model_out/`), not in the app:
- v1 woke on real audio 8 times an hour: the custom sound-alikes were only ~1 clip in 450.
- v2 fixed that (0.7/hour) but missed "Hey, Edith!" said with a pause.
- v3 (this one) added the paused clips.

## Retraining
About 22 GB of disk and ~1.5 hours on this PC. Work outside the repo (the data is large):
```
mkdir "D:\Dev Projects\edith-wakeword"; copy scripts\wakeword\* there (keep piper_gen\)
py -m uv venv --python 3.11 .venv
py -m uv pip install --python .venv\Scripts\python.exe torch==2.11.0 torchaudio==2.11.0 --index-url https://download.pytorch.org/whl/cu128
py -m uv pip install --python .venv\Scripts\python.exe -r requirements.txt
```
Then, in that folder:
1. Voices: download `en_US-libritts_r-medium.onnx` and `en_GB-vctk-medium.onnx` (each with its `.onnx.json`) from
   `huggingface.co/rhasspy/piper-voices` into `voices\`.
2. openWakeWord's features into `data\`: `openwakeword_features_ACAV100M_2000_hrs_16bit.npy` (16.5 GB) and
   `validation_set_features.npy` (180 MB) from `huggingface.co/datasets/davidscripka/openwakeword_features`.
3. `.venv\Scripts\python.exe -c "import openwakeword.utils as u; u.download_models(['hey_jarvis'])"`
4. `.venv\Scripts\python.exe prep_data.py` — room echoes, AudioSet 00–03, and the held-out shard 04.
5. `.venv\Scripts\python.exe check_voices.py` — the synthetic voices should wake openWakeWord's Hey Jarvis on
   "hey jarvis" (~99%) and not on "hey edith".
6. `.venv\Scripts\python.exe train_hey_edith.py` — writes `model_out\hey_edith.onnx`.
   (`train_hey_edith.py small` is a 10-minute dry run.)
7. `.venv\Scripts\python.exe evaluate.py model_out\hey_edith.onnx` and `check_sapi.py` (needs the Windows-voice
   clips in `sapi\`; see `OpenWakeWordDeviceTest` for two of them).
8. Copy it to `app\src\main\assets\wakeword\hey_edith.onnx`; `scripts/check.sh --device` runs `HeyEdithDeviceTest`.
