# Edith — handover notes for AI agents

> **Edith is being rebuilt from scratch (decided 2026-10-29).** Start with
> [`docs/design/README.md`](docs/design/README.md) — the complete design, split into chunks that can be
> implemented independently. The notes below describe the **old v1 app**, which chunk C01 removes; they're
> kept only as history. Don't build on v1 code.

Edith is a personal-assistant Android app (Kotlin, Jetpack Compose) whose "brain" is a **local
Ollama server on the owner's Windows PC**. These notes were written by the previous AI agent
(Claude Code, October 2026) for whoever takes the project over. They describe the design, the
current state, how to build and test, the decisions the owner has made, and the traps that cost
time. Read the whole file once; the "Owner's decisions" and "Gotchas" sections matter most.

Facts below were checked against the code and machine when written. If something here
disagrees with the code, trust the code and fix this file.

## 1. Quick start

```bash
# from D:\Dev Projects\edith  (Git Bash or PowerShell)
./gradlew.bat assembleDebug          # build the debug APK
./gradlew.bat installDebug           # build + install on the running emulator
adb shell am start -n com.edith.app/.MainActivity
```

Start the emulator first if it isn't running (it's often closed between sessions):

```powershell
Start-Process "$env:ANDROID_HOME\emulator\emulator.exe" -ArgumentList "-avd Pixel_9_API_37"
adb wait-for-device
# then poll until booted:  adb shell getprop sys.boot_completed   -> "1"
```

Ollama must be running on the PC (`ollama --version` → 0.40.11; it runs as a Windows background
app on port 11434). The app reaches it from the emulator at `http://10.0.2.2:11434`.

## 5. How the main features work

### Chat request (ChatViewModel.requestReply)
- Messages sent = `system` prompt + the whole visible history (`uiState.messages`).
- Every `ChatRequest` carries **`think: false`** and **`options.num_ctx = 16384`** by default
  (in `ChatRequest`'s defaults, `OllamaApi.kt`). Both matter:
  - gemma4's hidden "thinking" added 4–6 s per reply.
  - Ollama **reloads a model whenever `num_ctx` differs** between requests, and gemma4's default
    context (up to 262K) made Ollama evict other models. Keep *every* request on the same 16K
    (chat and transcription alike) or reloads (3–4 s each) come back.
- Non-streaming (`stream: false`). Replies appear whole.
- Errors are shown under the chat ("Couldn't reach Edith: …"); nothing fails silently.
- History is read from Room newest-first and reversed for display; `regenerateLastReply()` deletes
  the latest assistant row and asks again (only the newest reply can be regenerated).

### System prompt
Defined at the top of `ChatViewModel.kt`. Personality: warm, flattering but honest, witty,
"master planner". **The owner likes her personality — don't change it** (§8). Additions made
since: a conciseness instruction (2–4 sentences) and the attachment conventions below. It also
mentions tools (calendar, email, web search, transcription) that don't actually work (§7).

### Voice memos (record button = black dot)
1. First tap requests `RECORD_AUDIO` at runtime.
2. `RecordingManager` records 16 kHz mono 16-bit WAV (`AudioRecord`) to `cacheDir/recordings`.
3. Stop → `ChatViewModel.sendRecording()` → `AudioService.transcribe()` sends the WAV **base64 in
   the message's `images` field** (that's how Ollama takes audio) with a "transcribe verbatim"
   prompt; the model replies `[NO_SPEECH]` for silence (without that marker it apologised and the
   apology got sent as the user's question).
4. The transcript is sent as the user's message; the WAV is deleted.
- Ollama audio input accepts **WAV and MP3 only** (3GP/AMR and M4A return HTTP 400).
- Tested up to 86 s of speech in one request.

### Spoken replies
`VoiceService` uses the phone's `TextToSpeech` only — **no network calls** (owner's explicit
requirement). `speakReply()` respects the Settings switch; the play button (`speak()`) always
speaks. Speech stops when the user sends, records or dictates. `cleanForSpeech()` strips
attachment tags, markdown symbols and emoji.

### Reply action row
Under each Edith bubble: play (highlighted while that reply speaks), stop, and regenerate (latest
reply only). The row is deliberately pulled up 7 dp onto the bubble edge with a custom `layout`
modifier and has 32 dp buttons with `LocalMinimumInteractiveComponentEnforcement` off — the owner
asked for it "almost on top of the edge" and then said the current position is right. Keep it.

### Model dropdown (Settings)
`GET /api/tags` lists models; `POST /api/show` gives each model's `capabilities`. Models without
`completion` are hidden; models with `vision`/`audio` are labelled ("Understands images and audio
(voice memos)"). Reloads 600 ms after the URL stops changing; shows the error and "Tap to retry"
when unreachable; warns if the saved model isn't installed. Saving is still via "Save Settings".

### Attachments
- Paperclip in the text field → **Photo** (Android photo picker, no permission) or **Audio file**
  (`OpenDocument`, `audio/*`).
- `AttachmentReader` reads into **memory only**: photos decoded (EXIF-aware on API 28+), scaled to
  ≤1536 px, JPEG q85; audio kept as-is if WAV/MP3, otherwise decoded with MediaExtractor/MediaCodec
  and converted to 16-bit mono WAV in memory; audio capped at 5 minutes.
- Each attachment gets a session-unique number. User messages sent to Ollama carry labels like
  `[Attachment 3: receipt.jpg (image)]`, and the bytes (base64 in `images`) for the last
  `MEDIA_WINDOW = 10` messages only.
- Before sending media, the model's capabilities are checked; unsuitable models get a friendly
  error instead of a raw HTTP 400.
- Edith's conventions (taught in the system prompt, parsed by `ReplyFormat`):
  - `<file name="shopping-list.md">…</file>` → a file card (View / Save via SAF `CreateDocument` /
    Share as text). Unclosed `<file>` runs to the end of the reply.
  - `<attachment number="3"/>` → shows that live attachment again.
- **Storage:** only message text goes to Room. Attachments live in `ChatViewModel.liveAttachments`
  (keyed by Room row id; `insertHistory` returns the id). Edith's replies are stored with files
  reduced to `[Attached file: name]`; the full reply is kept in `liveReplies` for the session.
  After an app restart: user attachments vanish, files show "· only kept while the app was open",
  resent attachments show "Attachment N is no longer available". Audio plays from memory via
  `ByteArrayMediaDataSource`.
- Verified on the emulator: photo Q&A (she read a shopping-list image), M4A conversion (she
  understood a voice note), file cards produced unprompted, resend, a byte-level scan of the
  database + WAL (no image/audio/file content), and the restart behaviour.

## 6. Owner's decisions (respect these)

1. **Attachments exist only while the app is open — never stored in any form** (database, files,
   cache). The owner was emphatic. They have said they intend to revisit how attachments are
   stored and will specify it themselves — **don't change the storage behaviour until they do.**
   Saving one of Edith's files via its "Save" button (user-chosen location) is the only exception.
2. **Edith's voice is the phone's TextToSpeech, with no network calls.** A server voice (Orpheus via
   a Node helper) was built, crackled on the emulator, and was removed at the owner's request
   along with every trace of it. Don't reintroduce server speech unless asked.
3. **Don't change Edith's personality.** Conciseness was the one requested change.
4. **Google sign-in is optional**; chat, calendar (mock) and settings work without it.
5. Plain HTTP to Ollama is allowed (`usesCleartextTraffic="true"`) — fine for a home LAN app.
6. Look and feel the owner signed off on: bottom navigation; user bubbles purple on the right,
   Edith's grey on the left; compact single input row; action row hugging the bubble.

## 7. Known gaps and limitations (the honest list)

- **Rotating the phone (or signing in to Google) wipes everything "live".** `ChatViewModel` is
  created with `remember(account) { … }` in `MainScreen`, not as a real Android ViewModel, and
  `MainActivity` doesn't handle configuration changes. A rotation recreates the activity, so live
  attachments, pending (unsent) attachments, Edith's written files and any reply in progress are
  lost. Signing in changes `account`, which also recreates it. This undercuts the live-only
  attachment design — fix it (e.g. a proper `ViewModel` via a factory) before relying on "live"
  data surviving normal use. Chat text survives (it's in Room).
- **Chat history may be backed up to the cloud.** The manifest has `android:allowBackup="true"`,
  so Android Auto Backup can copy the Room database (message text, never attachments) to the
  phone owner's Google Drive. Given how the owner feels about stored data, raise this with them
  before release; `allowBackup="false"` or backup rules would stop it.
- **Tools are never called.** The app never sends Ollama a `tools` list, and `ChatResponse` looks
  for `tool_calls` at the top level of the response, but Ollama puts them in
  `message.tool_calls`. So `ToolExecutor` (calendar, email, web search, transcription) never runs,
  even though the system prompt tells Edith she has these tools. Wiring this up properly (Ollama
  `tools` schema + `message.tool_calls` + `role: "tool"` results) is the obvious next big feature.
- **Calendar and email are mock data.** `GoogleRepository` returns hard-coded events/emails;
  `GoogleApiService` response types don't match Google's real API shapes; there's no OAuth access
  token (`GoogleSignInAccount` doesn't carry one — would need `GoogleAuthUtil.getToken`).
- **Google sign-in can't work yet**: needs an OAuth client in Google Cloud Console for package
  `com.edith.app` + the debug SHA-1 above. `AuthManager` uses the deprecated `GoogleSignIn` API.
- **WebSearchService** calls DuckDuckGo but ignores the response and returns placeholder results;
  the query isn't URL-encoded.
- **No automated tests**, no CI on GitHub.
- **No app resources**: no `res/` folder. The manifest uses framework icon/theme
  (`@android:drawable/sym_def_app_icon`, `Theme.Material.Light.NoActionBar`). Status bar shows a
  black strip at the top in screenshots.
- **Emulator-only addressing**: `10.0.2.2` is the PC as seen from the emulator. A real phone needs
  the PC's LAN IP in Settings and a Windows firewall rule for port 11434. Ollama itself already
  listens on the LAN (`OLLAMA_HOST=0.0.0.0:11434`, §3).
- **Long conversations**: whole history is sent each time; with the 16K cap the oldest messages
  fall out of context eventually. Chat time grows with history (0.5 s fresh, 2–4 s with long history).
- **Speech starts only after the whole reply arrives** (non-streaming). Streaming `/api/chat` and
  speaking/showing sentence by sentence would make Edith feel faster.
- `ui/MainViewModel.kt` and `ui/CalendarViewModel.kt` are unused; `CalendarScreen` builds its own
  repository.
- Release build has never been tried (no signing config; `minifyEnabled false`).
- **Unused dependencies** in `app/build.gradle`: `navigation-compose`, `room-paging` and
  `play-services-location` are declared but nothing uses them (navigation is a hand-rolled enum in
  `MainScreen`; there's no paging or location code).
- **Settings save inconsistently**: server URL and model are saved only when "Save Settings" is
  tapped, but the "Speak Edith's replies" switch saves the moment it's toggled.
- **Dated libraries**: AGP 8.2.2, Kotlin 1.9.22, Compose BOM 2023.08 (Material 3 1.1). Upgrading is
  a project of its own; code that will need attention then includes `Modifier.menuAnchor()`,
  `LocalMinimumInteractiveComponentEnforcement`, `Icons.Filled.Send`/`VolumeUp` (now AutoMirrored)
  and Room's KSP setup.

Ollama platform facts learned (as of Oct 2026, Ollama 0.40.11): Ollama's own **text-to-speech
(`phonon`) and image generation need Apple's MLX and only run on Apple Silicon Macs** — on this
Windows PC `ollama pull phonon` fails with "requires MLX support". Audio *input* (gemma4) works.

## 9. Testing on the emulator (what worked)

There are no automated tests; everything was verified by driving the emulator with `adb`.

- **Find and tap UI elements** with uiautomator, not fixed coordinates:
  ```bash
  dump() { adb shell "uiautomator dump /sdcard/u.xml >/dev/null 2>&1; cat /sdcard/u.xml"; }
  tap() { b=$(dump | grep -o "$1[^>]*bounds=\"[^\"]*\"" | head -1 | grep -o '\[[0-9]*,[0-9]*\]\[[0-9]*,[0-9]*\]')
          read x1 y1 x2 y2 <<<$(echo "$b" | tr '[],' '   '); adb shell input tap $(( (x1+x2)/2 )) $(( (y1+y2)/2 )); }
  tap 'text="Message Edith"'; adb shell input text "Hello%sEdith"; adb shell input keyevent 4
  tap 'content-desc="Send"'
  ```
  Useful content descriptions: `Send`, `Record audio`, `Stop and send recording`, `Attach a file`,
  `Play reply`, `Stop playback`, `Regenerate reply`, `Speak a message`. Wait for replies by polling
  the dump until "thinking" disappears.
- **Screenshots**: `adb exec-out screencap -p > shot.png` (from Git Bash; PowerShell `>` corrupts binary).
- **App logs**: `adb logcat -s VoiceService:*` (logs each spoken reply); crashes: `adb logcat -b crash`.
- **App private files**: `adb shell run-as com.edith.app find . -type f`; copy a file out with
  `adb exec-out run-as com.edith.app cat <path> > out` (**not** `adb shell … cat`, which mangles bytes).
- **Test media**: generate speech with Windows SAPI from PowerShell
  (`System.Speech.Synthesis.SpeechSynthesizer` → `SetOutputToWaveFile`, 16 kHz mono) and images with
  ffmpeg `drawtext` (font `C\:/Windows/Fonts/arial.ttf`). Push to `/sdcard/Pictures` or `/sdcard/Music`
  and broadcast `android.intent.action.MEDIA_SCANNER_SCAN_FILE` so pickers see them. Delete test
  media afterwards.
- **Hitting Ollama directly** with small Node scripts (`fetch("http://localhost:11434/api/chat", …)`)
  is the fastest way to measure prompts, timings or audio handling without the app.
- **Proving what the app sent**: diff `%LOCALAPPDATA%\Ollama\server.log` before/after a test.
- **The emulator's chat history holds old test messages** from development (e.g. a stray user
  message "I'm sorry, but I can't hear any speech in this audio.", shopping-list and beach-day
  tests). Saved settings there: URL `http://10.0.2.2:11434`, model `gemma4:12b`, speech on.
  `adb shell pm clear com.edith.app` wipes all app data (history and settings) — ask the owner
  first; they also use the emulator.

## 10. Gotchas that cost time

- **Git Bash path conversion**: `adb push x /sdcard/...` becomes `C:/Program Files/Git/sdcard/...`.
  Use `MSYS_NO_PATHCONV=1` — and then give *local* paths in Windows form (`C:/Users/...`).
- **`sdkmanager` package names with `;`** get split by cmd. Use `--package_file=<file>`.
- **Photo picker on API 37** is select-then-**Done**, even for a single photo.
- **DocumentsUI search**: `adb shell input text` can get garbled by the keyboard ("voi_cenote");
  type short words.
- **Emulator mic records silence** (~-77 dB). To test speech for real, enable *Extended controls →
  Microphone → "Virtual microphone uses host audio input"*, or push a WAV/MP3 as an attachment.
- **Emulator audio crackles** when the PC is under heavy CPU load (it's the emulator's host audio
  path; Android reports zero underruns). Not an app bug.
- **The emulator is frequently closed between turns** (the owner closes it, or it exits). Check
  `adb devices` first; restart with the command in §1. App data usually survives, but not always.
- **The owner may be using the emulator at the same time as you** — unexpected messages in the chat
  are probably theirs; don't treat them as bugs.
- **Ollama model swapping**: any request with a different `num_ctx` reloads the model; a big default
  context can evict other models. `ollama ps` shows what's loaded and with what context.
- **`gemma4` "thinking" is on by default** — always send `think: false` unless reasoning is wanted.
- **Line endings**: Git converts to CRLF on checkout (warnings are normal). `gradlew` would get CRLF
  too — fine on Windows, broken on Linux/macOS; add a `.gitattributes` if that ever matters.
- **Room**: the `chat_history` schema is version 1 with no migrations. Any column change needs a
  version bump and a `Migration`, or existing installs crash.
- **Recovering the removed Orpheus voice server**: `git checkout c64d823 -- voice-server` (then
  `npm install` and `npm run setup`). It's a Node proxy on port 11435 that answered
  `/v1/audio/speech` with Orpheus (via Ollama) + the SNAC decoder (ONNX). Removed by owner request.
